# 45 秒软件拉新宣传短视频制作工作流

用于把任意桌面软件、Web 应用、CLI 工具或开源项目，制作成节奏紧凑、实机清晰、配音连贯、配乐均衡、可直接投放 **B站 / 抖音 / 小红书 / 知乎** 的 **45 秒（35–50s）拉新宣传短视频**与配套发布物料。

核心原则：**短片不是功能说明书，也不是架空故事会**。必须在 45 秒内让从未听说过该软件的新用户看懂三件事——**痛点是什么、软件长什么样、搜什么名字能找到**。

---

## 工作流总览（严格按顺序推进）

1. **产品提炼与定位锁定** → 提炼产品形态、信任背书、3–4 组痛点解法与唯一检索词
2. **45 秒分镜与口播设计** → 10–12 镜快节奏结构（前 3s 钩子 → 3–10s 全屏亮相 → 逐痛点拆解 → 结尾检索卡）
3. **Audio-First 连贯配音（TTS）** → 清缓存 + 指定内置音色 + 1.0x 原速连读，由自然气口反推每镜帧数
4. **全屏 + 局部放大双层视觉合成** → 全窗口定位 + 弹出式高清特写卡 + 多层剪纸投影动效
5. **全局节拍立体声配乐与混音校验** → 单一连续节拍网格 + 禁挖空中频 + `-8.5 ~ -7.0 dB` 响度门禁
6. **四平台定制封面与防限流文案** → 避开各平台 UI 遮挡的安全区封面 + 合规无外链文案

---

## 步骤 1：产品提炼与定位锁定

动笔写分镜前，先从用户需求或项目 README/实机界面中锁定以下 4 项要素（缺一不可）：

1. **一句话产品形态**：明确告诉新用户“这是什么”（例如 `Windows 桌面端软件`、`VS Code 插件`、`本地 CLI 工具`、`Web 工作台`），严禁只讲抽象概念不亮形态。
2. **核心信任背书**：提炼 1–2 个硬背书（如 `GitHub X,000+ Star`、`免费开源`、`本地优先离线可用`、`MIT 协议`）。
3. **3–4 组直击痛点的对比**：每组只讲 **“传统做法怎么崩 → 本软件如何一招解决”**。
   - **严禁编造与软件无关的虚构剧情人物或隐喻故事**（例如用古代客栈/钥匙讲现代软件），新用户没有耐心猜谜语，所有视觉隐喻必须一眼看懂。
4. **唯一检索关键词 `<BrandSearchTerm>`**：全片标题、口播、结尾搜索卡片、四大平台文案必须统一引导搜索同一个最易记忆的词（避免中英混杂导致搜索分流）。

## 步骤 2：45 秒分镜与节奏控制

- 严格控制在 **38–48 秒**（推荐 **45 秒**，拆为 **10–12 镜**，平均每镜 `3.5s–4.5s`）。2 分钟视频在短视频信息流中过于拖沓，除非用户明确要求长教程，否则默认 45 秒。
- **一镜一件事，禁止单镜内碎切**：不要在 4 秒镜头里切 3 个子画面（会产生抽搐感），也不要让画面静止超过 `0.35s`（像 PPT）。每镜内部采用平滑的三段接力动作：`入场 (0–0.28)` → `定位/放大/核心变化 (0.28–0.74)` → `印章/标签反馈 (0.70–0.96)`。
- **前 10 秒黄金结构**：
  - `S01 (0–3.5s)`：痛点暴击钩子（用失败场景直接提问）。
  - `S02 (3.5–7.5s)`：**满幅全屏实机亮相** + 核心背书贴纸（如 Star 数/开源）。
  - `S03 (7.5–11.5s)`：全屏结构总览（用红框+箭头依次点亮软件核心分区）。

详细 11 镜模板与文案规范见：[references/storyboard-and-copy-playbook.md](./references/storyboard-and-copy-playbook.md)。

## 步骤 3：Audio-First 连贯配音（TTS）

短视频拉新默认**必须带口播解说**（除非用户明确要求无配音纯音乐）。配音节奏直接决定成片是否自然：

1. **先清缓存再生成**：重新制作或换音色前，必须清空 `voice/` 下的旧 `.wav` 与临时 take，防止脚本复用旧音频。
2. **禁止使用个人克隆音色**：严禁硬编码任何 `voice_*` 克隆 ID；必须显式使用模型自带的官方标准预设音色（如 Gemini TTS 的 `Puck` / `Aoede` 等），并在代码中用 `assert` 锁死音色 ID。
3. **1.0x 原速连贯生成，禁止逐句变速拼接**：
   - **为什么**：把 12 句话拆开逐句调用 TTS、再分别套用不同的 `atempo` 变速强行塞进固定秒数，会导致每句语速飘忽、句间出现机械断气，听感极其别扭。
   - **正确做法**：将全片台词按自然标点一次性（或最多按开场/功能/结尾 3 段）**1.0x 原速连贯生成**，在句间自然气口处保留 `0.12s–0.18s` 停顿。
4. **以声定画（Audio-First）**：运行 [scripts/derive_shot_frames.py](./scripts/derive_shot_frames.py) 识别连贯语音中的自然气口低谷，自动输出 `timing.json`（每镜起止帧数），由声音反推切镜点（仅在片尾停留帧微调总长）。

详细 TTS API 请求体、音色提示词与参数规范见：[references/audio-tts-and-mixing-spec.md](./references/audio-tts-and-mixing-spec.md)。

## 步骤 4：全屏实机 + 局部放大双层视觉合成

截取软件实机图时，先获取完整的全窗口高清截图（如 `1440x900` 或 `1920x1080`），严禁只裁剪孤立的局部小窗或把整屏软件缩成看不清文字的角落贴片。

采用以下两种构图结合：
1. **满幅全屏构图（亮相 / 总览 / 结尾衬底）**：
   - 将完整软件窗口嵌入窄边纸艺框中**居中满幅展示（占画面宽度 `86%–90%`）**；角标、Star 徽章以轻量纸艺贴纸叠在边缘，**不要用宽大的左侧文字栏把主屏幕挤小**。
2. **全屏底图定位 + 弹出高清局部特写卡（所有功能演示镜）**：
   - **阶段 1 (`0%–32%`)**：全屏展示完整软件窗口，在目标功能区域动态绘制红框与引导箭头，让观众先看清“这个功能在软件哪个位置”；
   - **阶段 2 (`32%–100%`)**：底层全屏窗口保持原位并轻微压暗（约 `18%`）作为空间锚点，从红框位置拉出两条引导线，平滑弹出带手工纸艺白边与高斯投影的**高清局部特写卡（占屏宽 `58%–66%`）**，后段落下确认印章或结果标签。
3. **双语字幕条**：底部统一设置纸艺字幕条，**中文在上、英文在下**，居中对齐，每句中文控制在 16 字以内，确保与特写卡不重叠。

可参考并复用：[scripts/render_callout_template.py](./scripts/render_callout_template.py) 与 [references/visual-compositing-spec.md](./references/visual-compositing-spec.md)。

## 步骤 5：全局节拍立体声配乐与混音校验

1. **全局单一节拍网格（根治错拍与重复怪音）**：
   - **为什么**：如果在 `for shot` 循环内用 `np.arange(s, e, beat)` 按镜头起始秒重置节拍，124/136 BPM 无法与镜头整数秒对齐，每次切镜都会产生鼓手踩空般的“双连错拍底鼓”。
   - **正确做法**：用单一全局循环 `for beat_idx in range(total_beats):` 贯通全片；**禁止**在痛点镜插错拍抽搐底鼓或跑调刺耳单音；**禁止**在盖章音效处叠加额外底鼓。
2. **饱满立体声编曲 + 严禁挖空中频**：
   - 必须包含立体声展开的和弦铺底（`pan = ±0.38`）、跳跃旋律动机（`pan = ±0.45`）、Bassline 与四四拍轻快鼓组。
   - **严禁**对音乐使用 `500–2800Hz` 带阻滤波器（`bandstop`）挖空中频，这会直接导致“背景音乐等于没有”。
3. **响度比例门禁**：人声居中并归一至约 `-14 LUFS`；根据语音包络平滑侧链闪避后，必须运行 [scripts/check_audio_mix.py](./scripts/check_audio_mix.py) 验证：
   - 说话期间 `BGM_RMS_dB - Speech_RMS_dB` 严格落在 **`[-8.5, -7.0] dB`**（外放清晰动听且不盖人声），未通过校验不得交付成片。

## 步骤 6：四平台定制封面与防限流发布包

出片时同步渲染 4 张避开平台 UI 遮挡的封面图，并生成适配各平台语境的标题与简介：

- **封面尺寸与安全区**：
  - `cover_bilibili.jpg` (`1280x720`)：全屏实机 + 痛点/背书标签，**右下角留空**避开时长角标。
  - `cover_douyin.jpg` (`1280x720`)：核心大字与实机居中偏上（安全区 `70%`），**底部与右侧各留白 15%** 避开文案与点赞栏。
  - `cover_xhs_3x4.jpg` (`1080x1440`)：3:4 竖版纸艺海报，顶部大标题 + 中间实机 + 底部 15% 安全区三枚核心标签。
  - `cover_zhihu.jpg` (`1280x720`)：克制高级的知识分享排版，重点呈现“为什么传统方案不行 + 结构化实机”。
- **防限流红线**：
  - 文案正文**绝不放外链网址、二维码、微信号/群号**，不写“私信领”“扣1发安装包”“全网最强/吊打/神器/白嫖”；
  - 统一引导搜索 `<BrandSearchTerm>`；
  - 提示发布者主动勾选平台**“含 AI 辅助创作”**声明。

详细像素安全区与平台文案模板见：[references/storyboard-and-copy-playbook.md](./references/storyboard-and-copy-playbook.md)。
